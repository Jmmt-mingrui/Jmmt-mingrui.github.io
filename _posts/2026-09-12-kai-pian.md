这个博客最初不是这样的。

最初它是一个 Next.js 16 项目，带着 Cloudflare Workers 运行时、Drizzle ORM、Vitest 测试套件、21 个 npm 依赖、792MB 的 node_modules。装一次依赖要等十几分钟。写一篇 Markdown 文章之前，要先确认 Node 版本对不对、wrangler 配置有没有改、CI 是不是绿的。

说实话，那套东西挺酷的。SSR、边缘计算、图片优化、全文搜索——该有的都有。但有一天我突然意识到一件事：

**我一个写 Markdown 的博客，为什么要维护八百多行代码？**

## 转折

我看了两个人的博客。

一个是姚顺雨的 [ysymyth.github.io](https://ysymyth.github.io/)——ReAct 和 Tree of Thoughts 的作者，OpenAI 的研究员。他的站是 Jekyll，配置文件 40 行，5 篇 Markdown 文章。没有任何构建脚本，没有任何 npm 依赖。push 上去就上线。

另一个是 [diygod.cc](https://diygod.cc/)——DPlayer 和 xLog 的作者。他的站是 Astro + Tailwind，看起来精致克制，悬停有虚线下划线，封面是 16:9 的圆角卡片。但它背后是一个完整的前端项目，依赖和构建一样不少。

两个人，两种路线。但有一个共同点：**他们的博客都是他们自己写的，不是套模板套出来的。**

我想要的是：diygod 的那种视觉质感，姚顺雨的那种构建简洁。要那张脸，不要那套装备。

## 所以变成了这样

现在你看到的这个站：

- **Jekyll**，GitHub Pages 原生支持，零依赖、零构建脚本
- 样式是自己写的 CSS，没有引外部字体、没有引 CDN
- 深色模式是 30 行原生 JS + CSS 变量
- 仿 diygod 的开场：左右分栏、大圆角头像、虚线分隔线、胶囊标签
- 代码在 [GitHub](https://github.com/Jmmt-mingrui/Jmmt-mingrui.github.io)，push Markdown 即发布

上一版的 Next.js 项目没删，存在 `nextjs-legacy` 分支里。万一哪天想回去还能找到。但我知道不会回去了。

## 接下来写什么

不说"我会写技术笔记"这种空话。直接列几篇已经在脑子里的：

- **Go 的 GMP 调度模型到底在干什么**——面试被问过，当时答得不好，回来从头看了一遍
- **MCP 协议是怎么让 AI 调用工具的**——做了 doris-mcp-server 之后想整理一下设计思路
- **秋招复盘**——哪些问题答得好、哪些答砸了、为什么
- **微服务从零搭一套是什么体验**——microservices-go 这个项目的实战记录

不知道能写多少篇、多久写一篇。但有一件事是确定的：**不会再为了"更新博客"而写水文。** 写出来的东西，三个月后自己回来看，得还觉得有用。

## slogan

「写代码是热爱，写到世界充满爱！」

这句话来自 diygod。我借来用，是因为它恰好说出了我想做的事——写代码本身是一件快乐的事，而把学到的东西写下来、分享出去，是让这份快乐传递出去的方式。

不多说了。下一篇就是真正的技术内容。
